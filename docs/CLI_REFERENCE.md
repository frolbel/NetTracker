# Справочник командной строки NetTracker

NetTracker поддерживает множество параметров для управления мониторингом, экспортом, аналитикой и форматированием вывода.

## Базовое использование
```cmd
NetTracker.exe <имя_процесса_1> [имя_процесса_2] ... [опции]
```

---

## Флаги и параметры

### 1. Управление UAC (Права администратора)
*   **`--elevate`** (или **`-e`**)
    Запускает утилиту с запросом прав администратора (UAC) в новом окне оболочки, сохраняя все переданные аргументы. Если флаг не указан, а прав нет, утилита выдаст ошибку в текущую консоль `Для работы программы необходимы права администратора.` и звершит работу с кодом `5` (Access Denied), см. [Коды возврата \(Exit Codes\)](#коды-возврата-exit-codes).

### 2. Экспорт данных в реальном времени
*   **`--out="<путь>"`** (или **`-o="<путь>"`**)
    Включает сбор данных и сохраняет результаты в указанный файл после завершения работы (по Ctrl+C).
*   **`--type=<формат>`** (или **`-t=<формат>`**)
    Принудительно задает формат экспорта. Возможные значения:
    *   `raw` — простая текстовая таблица (как в консоли).
    *   `csv` — файл с разделителем `;` (удобно для Excel).
    *   `json` — массив структурированных объектов.
    *   `host` — формат файла hosts (IP и домен через табуляцию). Исключает дубликаты.
    *   `dummy` — формат hosts[^1], но все IP-адреса заменяются на `127.0.0.1` (идеально для создания блокировки на основе hosts[^2]).

[^1]: Файл hosts в Windows — это системный текстовый файл, который позволяет вручную сопоставлять доменные имена с IP-адресами. При обращении к сайту система сначала проверяет этот файл: если для домена есть запись, используется указанный IP-адрес, и только после этого идёт запрос к DNS-серверам.  
[^2]: По умолчанию файл расположен по пути: `C:\Windows\System32\drivers\etc\hosts`, но расположение файла может быть переопределено в реестре. Проверьте параметр `DataBasePath` в разделе `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters`. Если значение отличается от стандартного, файл может находиться в другой папке.

💡 **Умные умолчания:** Программа автоматически определяет формат экспорта по расширению файла в параметре `--out` (`.json`, `.csv`, `.raw`). Если расширение неизвестно, по умолчанию используется `host`.

### 3. Оффлайн-анализ (Импорт)
*   **`--in="<путь>"`** (или **`-i="<путь>"`**)
    Режим конвертации и пост-анализа. Программа не запускает ETW-мониторинг и **не требует прав администратора**. Она загружает исторические данные из `.json` или `.csv` файла, выводит их на экран и позволяет применить к ним экспорт (`--out`) или генерацию статистики (`--stats`).

### 4. Аналитика и статистика
*   **`--stats`**
    Выводит подробный аналитический отчет в консоль после завершения сбора данных (или после импорта). Отчет включает разрешенные DNS, список публичных IP без DNS, детекцию локальных интерфейсов и анализ аномальных всплесков активности (Bursts).
*   **`--stats="<путь>"`**
    То же самое, но дополнительно сохраняет отчет в указанный текстовый файл.

### 5. Уровни детализации консоли (Log Level)
*   **`--loglevel=<уровень>`** (или **`-l=<уровень>`**)
    Управляет тем, что выводится на экран. Можно указывать число или название:
    *   `0` (`Error`) — только критические ошибки.
    *   `1` (`Warning`) — ошибки и предупреждения.
    *   `2` (`Capture`) — вывод перехваченных соединений (таблица).
    *   `3` (`Statistics`) — вывод аналитической статистики (если запрошена).
    *   `4` (`Info`) — статусные сообщения (импорт/экспорт/старт сессии).
    *   `5` (`Debug`) — отладочная информация (уровень по умолчанию).
    *   `6` (`Trace`) — низкоуровневая трассировка ETW.

## Динамические шаблоны путей

NetTracker поддерживает встроенный шаблонизатор для путей сохранения (`--out` и `--stats`). Это предотвращает перезапись файлов при циклическом или фоновом запуске.

Синтаксис: `{%лексема:формат}`

*   **`%date`** — текущая дата (формат по умолчанию `yyyy-MM-dd`).
*   **`%time`** — текущее время (формат по умолчанию `HHmmss`).

**Примеры использования:**
```cmd
:: Автоматическая подстановка времени и автовыбор формата CSV
NetTracker.exe chrome --out="C:\Logs\chrome_{%date_%time}.csv"

:: Явное указание формата времени через двоеточие
NetTracker.exe telegram --out=".\dumps\tg_{%date:yyyy.MM.dd_%time:HH-mm}.json"

:: Использование шаблона для отчета статистики
NetTracker.exe yandex --stats=".\reports\stats_{%date}.txt"
```

## Коды возврата (Exit Codes)

NetTracker использует стандартизированные коды возврата для удобной интеграции в скрипты автоматизации (например, `.bat` или PowerShell).

- `0` (Success) — Утилита успешно завершила работу (пользователь нажал Ctrl+C или закрыл окно).
- `5` (AccessDenied) — Ошибка доступа. Утилита запущена без прав администратора из консоли, флаг `--elevate` не передан.  
- `160` (BadArguments) — Некорректные аргументы. Указаны неверные флаги или не передано имя процесса.
- `740` (ElevatedRelaunch) — Утилита потребовала повышения прав (UAC) и была успешно перезапущена в новом окне администратора. Текущий процесс завершен.  

**Пример:** Запуск утилиты в PowerShell без прав администратора:  
```powershell
PS > .\NetTracker.exe chrome
Ошибка: Для работы NetTracker требуются права администратора.
Запустите оболочку от имени администратора или используйте флаг --elevate (-e) для запуска в новом окне.
PS > Write-Host "Exit code: $LASTEXITCODE"
Exit code: 5
PS > .\NetTracker.exe chrome --elevate
Для работы программы необходимы права администратора.
PS > Write-Host "Exit code: $LASTEXITCODE"
Exit code: 5
PS > .\NetTracker.exe chrome --elevate
PS > Write-Host "Exit code: $LASTEXITCODE"
Exit code: 740
PS >
```
