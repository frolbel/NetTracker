# Сравнение NetTracker с альтернативными инструментами

| Инструмент | Преимущества | Недостатки |
| :--- | :--- | :--- |
| **Монитор ресурсов** | Встроен в Windows(`resmon`). | Не записывает историю: если соединение закрылось, оно мгновенно исчезает из списка. Нет лога DNS. |
| **[TCPView](https://learn.microsoft.com/ru-ru/sysinternals/downloads/tcpview)** (Sysinternals) | Привычный GUI. | Акцент на текущих сессиях. Не сохраняет связь "IP - Домен" для уже закрытых соединений. |
| **Команда netstat** | Команда `netstat` есть везде, работает в цикле[^1]. | **Метод опроса:** делает периодические «снимки» системы (Polling) и пропускает кратковременные коннекты. Не показывает домены[^2]. |
| **[Fiddler Classic](https://www.telerik.com/fiddler/fiddler-classic)** | Анализ HTTP/HTTPS. | Требует установки прокси и сертификатов. Не видит трафик, идущий не по HTTP. |
| **[Wireshark](https://www.wireshark.org/)** | Полный захват пакетов. | Слишком сложен[^3]. Требует установки драйверов (Npcap). Логи забиты техническим "шумом". |

[^1]: Если выполнить команду `netstat -ano 1` с числовым аргументом в конце, она будет обновляться каждую секунду.  
[^2]: `netstat` показывает либо только IP-адреса (-n), либо пытается сделать обратный DNS-резолвинг (**Reverse DNS**), который работает очень медленно и часто выдает нечитаемые технические имена (**PTR-записи**). **В отличие от него, NetTracker** перехватывает "живые" DNS-ответы: он видит ровно то же самое, что и само приложение, поэтому доменные имена в логах всегда актуальны и понятны.  
[^3]: Чтобы отфильтровать трафик нужной программы, проще всего сначала узнать используемый её порт или IP-адрес сервера через **Монитор ресурсов** (`resmon`), а затем вбить в строку фильтра **[Wireshark](https://www.wireshark.org/)** фильтр вида: `ip.addr == 192.168.x.x` (где IP — адрес сервера).

### Ключевое преимущество NetTracker - событийная модель
В отличие от команды `netstat` или **«Монитора ресурсов»** (`resmon`), которые делают периодические «снимки» системы (Polling), **NetTracker** работает на базе **событий ядра**, т.е. в отличие от обычных утилит, использующих опрос таблицы соединений (как `netstat`), **NetTracker** подписывается на системные события. Когда целевое приложение выполняет DNS-запрос, утилита запоминает связку "IP-Домен". При последующем TCP-подключении программа мгновенно выводит понятное имя хоста.

Это дает два решающих преимущества:
1. **Ничего не будет пропущено:** Если приложение установило соединение всего на 0.01 сек, **NetTracker** зафиксирует его, в то время как команда `netstat` его просто не заметит.
2. **Живой DNS-резолвинг:** **NetTracker** связывает TCP-пакеты с конкретными DNS-ответами, которые приходят приложению «здесь и сейчас». Вы видите реальные домены, а не "голые" IP-адреса.
