# NetTracker

**NetTracker** — это компактная консольная утилита на C#, предназначенная для мониторинга сетевой активности конкретного приложения в Windows в режиме реального времени.

Программа использует механизм **Event Tracing for Windows (ETW)**, что позволяет перехватывать события на уровне ядра ОС. Это гарантирует, что ни одно кратковременное сетевое соединение не будет пропущено.

## Особенности
- **Точность:** Захват TCP-соединений через Kernel-провайдер Windows.
- **DNS Resolution:** Автоматическое сопоставление IP-адресов с реальными именами доменов путем перехвата системных DNS-ответов.
- **Стабильность:** Уникальная идентификация сессии (`frolbel.NetTracker.Session`) и механизм автоматической очистки ресурсов при запуске и выходе.
- **Фильтрация:** Отслеживание трафика только для указанного пользователем процесса.

## Как это работает
В отличие от обычных утилит, использующих опрос таблицы соединений (как `netstat`), NetTracker подписывается на системные события. Когда целевое приложение выполняет DNS-запрос, утилита запоминает связку "IP-Домен". При последующем TCP-подключении программа мгновенно выводит понятное имя хоста.

## Требования
- Операционная система: Windows 10/11 x64.
- **Права Администратора:** Необходимы для доступа к трассировке событий ядра (ETW).

## Использование
Вы можете использовать NetTracker двумя способами:

### Способ 1: Готовый файл
1. **Обычный запуск (Рекомендуемый)**  
   1.1. Перейдите в раздел [Releases](https://github.com/frolbel/NetTracker/releases) и скачайте последнюю версию `NetTracker.exe`.   
   1.2. Просто дважды кликните по файлу `NetTracker.exe` в проводнике.  
   1.3. Приложение запросит права администратора (UAC) — согласит  есь.  
   1.4. В открывшемся окне введите имя процесса (например, chrome или telegram) и нажмите Enter.  
   1.5. Дождитесь, пока соберется достаточное количество данных, и нажмите сочетание клавиш Ctrl+C. 
   1.6. Окно не закроется сразу — программа выведет сообщение: "Сбор данных завершен. Нажмите любую клавишу, чтобы выйти...".  
   1.7. Теперь вы можете спокойно выделить нужные строки мышью и скопировать их (нажав Enter или Ctrl+C).  
   1.8. После того как скопируете всё необходимое, нажмите любую клавишу для закрытия окна.  
2. **Запуск через командную строку** — для тех, кто привык работать из консоли.  
   2.1. Перейдите в раздел [Releases](https://github.com/frolbel/NetTracker/releases) и скачайте последнюю версию `NetTracker.exe`.
   2.2. Запустите терминал (PowerShell или CMD) **от имени Администратора**.
   2.3. Запустите файл: `.\NetTracker.exe`

### Способ 2: Сборка из исходников
1. Склонируйте репозиторий.
2. Установите [.NET 9.0 SDK](https://dotnet.microsoft.com/download/dotnet/9.0).
3. Соберите проект: `dotnet publish -c Release -r win-x64 --self-contained`.
4. Запустите полученный файл от имени Администратора.

## Работа с программой
1. Введите имя процесса (например, `telegram`, `discord` или `firefox`).
2. Для завершения сбора статистики и вывода итогового списка уникальных ресурсов нажмите `Ctrl+C`.
3. После завершения программа дождется нажатия любой клавиши перед закрытием окна.

## Частые вопросы и особенности (FAQ)

### Почему я вижу много строк "Неизвестный домен (прямой IP)"?

Если вы отслеживаете современные браузеры (Chrome, Edge, Firefox) или некоторые другие приложения, вы можете заметить много соединений без доменного имени. Этому есть несколько причин:

1. **Использование "Безопасного DNS" (DNS-over-HTTPS / DoH)**
   Современные браузеры по умолчанию шифруют DNS-запросы и отправляют их напрямую на серверы (например, Google или Cloudflare) по HTTPS. Из-за этого запросы не проходят через системную службу DNS Windows, и NetTracker (через ETW) их не видит.
   * **Решение (для Chrome):** Откройте `chrome://settings/security`, найдите раздел **"Использовать безопасный DNS-сервер"** (Use secure DNS) и временно **отключите** его.
   * **Решение (для Edge):** Откройте `edge://settings/privacy`, прокрутите до раздела "Безопасность" (Security), найдите **"Использовать безопасный DNS..."** (Use secure DNS) и **отключите** его.
   * **Решение (для Яндекс.Браузера):** Откройте `browser://settings/security` (или Настройки -> Безопасность), найдите **"Использовать безопасный DNS-сервер"** и **отключите** его.
   * **Решение (для Firefox):** Откройте настройки (`about:preferences`), перейдите в раздел **"Приватность и защита"** (Privacy & Security), прокрутите вниз до **"DNS через HTTPS"** (DNS over HTTPS) и выберите **"Отключить"** (Off).

2. **Внутренний кеш браузера**
   Сброс кеша Windows (`ipconfig /flushdns`) не влияет на браузеры — у них свой собственный, очень агрессивный кеш DNS и установленных соединений (Socket Pools).
   * **Решение (для Chrome):** 
     1. Перейдите по адресу `chrome://net-internals/#dns` и нажмите **Clear host cache**.
     2. Перейдите по адресу `chrome://net-internals/#sockets` и нажмите **Flush socket pools**.
   * **Решение (для Edge и Яндекс.Браузера):** Делается точно так же, как в Chrome, только используются другие внутренние адреса:
     * Для Edge: `edge://net-internals/#dns` и `edge://net-internals/#sockets`
     * Для Яндекс.Браузера: `browser://net-internals/#dns` и `browser://net-internals/#sockets`
   * **Решение (для Firefox):**
     1. Перейдите по адресу `about:networking#dns` и нажмите кнопку **Очистить кэш DNS** (Clear DNS Cache).
     2. У Firefox нет отдельной кнопки для сброса сокетов, поэтому после очистки DNS-кеша рекомендуется просто **перезапустить браузер**.

3. **Реальные прямые IP-адреса**
   Некоторые соединения действительно происходят напрямую по IP-адресу без участия DNS:  
   * Локальные прокси-серверы (например, `127.0.0.1:8080` для Nekobox/Xray).  
   * Запросы к локальному роутеру (например, `192.168.1.1` или `192.168.1.1:53`).
   * Приложения, в которых IP-адреса жестко прописаны в коде (hardcoded).
