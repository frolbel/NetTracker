# NetTracker

**NetTracker** — это компактная консольная утилита для Windows. Она позволяет выбрать любое приложение (например, браузер, мессенджер или незнакомую программу) и в реальном времени увидеть, к каким серверам в сети оно подключается и какие DNS-имена запрашивает.

Утилита использует механизм **Event Tracing for Windows (ETW)**, что позволяет перехватывать события на уровне ядра ОС. Это гарантирует, что ни одно кратковременное сетевое соединение не будет пропущено и позволяет получать информацию о нём без установки драйверов или захвата пакетов.

## Особенности
- **Высокая точность:** Захват TCP-соединений в реальном времени через Kernel-провайдер Windows (ETW), что гарантирует обнаружение каждого сетевого события без нагрузки на процессор.
- **DNS Resolution:** Автоматическое сопоставление IP-адресов с реальными именами доменов путем перехвата и сопоставления системных DNS-ответов (Microsoft-Windows-DNS-Client).
- **Мониторинг группы процессов:** Возможность одновременного отслеживания трафика нескольких приложений (например, браузера и прокси-клиента).
- **Интеллектуальная фильтрация:** Утилита отображает трафик только для указанных пользователем процессов, отсекая лишний системный шум.
- **Стабильность и гигиена:** Использование уникального идентификатора сессии (`frolbel.NetTracker.Session`) с механизмом автоматической очистки зависших сессий при запуске и корректным освобождением ресурсов при выходе.
- **Zero-Dependency:** Не требует установки драйверов (как WinPcap/Npcap) или сторонних анализаторов трафика. Работает как единый переносимый файл (`Single File Executable`).

## Как это работает
В отличие от обычных утилит, использующих опрос таблицы соединений (как `netstat`), **NetTracker** подписывается на системные события. Когда целевое приложение выполняет DNS-запрос, утилита запоминает связку "IP-Домен". При последующем TCP-подключении программа мгновенно выводит понятное имя хоста.

## Сравнение NetTracker с альтернативными инструментами

| Инструмент | Преимущества | Недостатки |
| :--- | :--- | :--- |
| **Монитор ресурсов** | Встроен в Windows(`resmon`). | Не записывает историю: если соединение закрылось, оно мгновенно исчезает из списка. Нет лога DNS. |
| **[TCPView](https://learn.microsoft.com/ru-ru/sysinternals/downloads/tcpview)** (Sysinternals) | Привычный GUI. | Акцент на текущих сессиях. Не сохраняет связь "IP - Домен" для уже закрытых соединений. |
| **Команда netstat** | Команда `netstat` есть везде, работает в цикле[^1]. | **Метод опроса:** делает периодические «снимки» системы (Polling) и пропускает кратковременные коннекты. Не показывает домены[^2]. |
| **[Fiddler Classic](https://www.telerik.com/fiddler/fiddler-classic)** | Анализ HTTP/HTTPS. | Требует установки прокси и сертификатов. Не видит трафик, идущий не по HTTP. |
| **[Wireshark](https://www.wireshark.org/)** | Полный захват пакетов. | Слишком сложен[^3]. Требует установки драйверов (Npcap). Логи забиты техническим "шумом". |

[^1]: Если выполнить команду `netstat -ano 1` с числовым аргументом в конце, она будет обновляться каждую секунду.  
[^2]: `netstat` показывает либо только IP-адреса (-n), либо пытается сделать обратный DNS-резолвинг (**Reverse DNS**), который работает очень медленно и часто выдает нечитаемые технические имена (**PTR-записи**). **В отличие от него, NetTracker** перехватывает "живые" DNS-ответы: он видит ровно то же самое, что и само приложение, поэтому доменные имена в логах всегда актуальны и понятны.  
[^3]: Чтобы отфильтровать трафик нужной программы, проще всего сначала узнать используемый её порт или IP-адрес сервера через **Монитор ресурсов** (`resmon`), а затем вбить в строку фильтра **[Wireshark](https://www.wireshark.org/)** фильтр вида: `ip.addr == 192.168.x.x` (где IP — адрес сервера).

### Ключевое преимущество NetTracker - событийная модель
В отличие от команды `netstat` или **«Монитора ресурсов»** (`resmon`), которые делают периодические «снимки» системы (Polling), **NetTracker** работает на базе **событий ядра**. 

Это дает два решающих преимущества:
1. **Ничего не будет пропущено:** Если приложение установило соединение всего на 0.01 сек, **NetTracker** зафиксирует его, в то время как команда `netstat` его просто не заметит.
2. **Живой DNS-резолвинг:** **NetTracker** связывает TCP-пакеты с конкретными DNS-ответами, которые приходят приложению «здесь и сейчас». Вы видите реальные домены, а не "голые" IP-адреса.

## Требования
- Операционная система: Windows 10/11 x64.
- **Права Администратора:** Необходимы для доступа к трассировке событий ядра (ETW).

## Как получить утилиту

### Способ 1: Готовый файл (Рекомендуемый)  
Вы можете скачать уже скомпилированный исполняемый файл, который не требует установки:  
1. Перейдите в раздел **[Releases](https://github.com/frolbel/NetTracker/releases)**.
2. Скачайте файл `NetTracker.exe`.  
3. **Проверьте целостность (рекомендуется):**   
   - На странице релиза рядом с файлом в списке `Assets` найдите значение `sha256:...` и скопируйте его (кнопка с иконкой двух квадратов).
   - В папке со скачанным файлом откройте **PowerShell** и выполните команду:
     ```powershell
     Get-FileHash .\NetTracker.exe -Algorithm SHA256
     ```
   - Убедитесь, что значение в колонке `Hash` совпадает со скопированным с сайта.

### Способ 2: Сборка из исходников
Если вы хотите собрать программу самостоятельно, вам понадобится **.NET 9.0 SDK**:
1. Склонируйте репозиторий.  
2. Выполните команду в папке проекта:     
```bash   
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
```  
3. Готовый файл появится в папке `bin/Release/net9.0/win-x64/publish/`.  

## Использование  
Для работы утилиты требуются права администратора (т.е. запускать **от имени Администратора**), так как она использует системные события *ETW*.

### Вариант 1: Интерактивный запуск (Самый удобный)  
Позволяет легко копировать результаты после завершения:  
1. Дважды кликните по файлу `NetTracker.exe` в проводнике.    
2. Программа запросит права администратора (UAC) — подтвердите.   
3. Введите одно или несколько имен процессов через пробел или запятую (например: chrome, telegram, discord) и нажмите `Enter`.    
4. Для остановки сбора данных нажмите `Ctrl+C`.  
5. Окно останется открытым: вы можете выделить текст мышью и скопировать его.  
6. Нажмите любую клавишу для выхода.  

### Вариант 2: Запуск с аргументами (Консоль)  
Удобно для использования в скриптах или если консоль уже открыта:  
1. Запустите `cmd` или `PowerShell` **от имени Администратора**.  
2. Запустите утилиту:  
```cmd
.\NetTracker.exe <имя_процесса1> <имя_процесса2>
```

Пример: `.\NetTracker.exe chrome telegram` или `NetTracker.exe chrome.exe Telegram.exe`

## Частые вопросы и особенности (FAQ)

### Почему я вижу много строк "Неизвестный домен (прямой IP)"?  
Если вы отслеживаете современные браузеры (Chrome, Edge, Firefox, Яндекс.Браузер и т.п.) или некоторые другие приложения, вы можете заметить много соединений без доменного имени. Этому есть несколько причин:

1. **Использование "Безопасного DNS" (DNS-over-HTTPS / DoH)**
   Современные браузеры по умолчанию шифруют DNS-запросы и отправляют их напрямую на серверы (например, Google или Cloudflare) по HTTPS. Из-за этого запросы не проходят через системную службу **DNS Windows**, и **NetTracker** (через ETW) их не видит.
   * **Решение (для Chrome):** Откройте `chrome://settings/security`, найдите раздел **"Использовать безопасный DNS-сервер"** (Use secure DNS) и временно **отключите** его.
   * **Решение (для Edge):** Откройте `edge://settings/privacy`, прокрутите до раздела "Безопасность" (Security), найдите **"Использовать безопасный DNS..."** (Use secure DNS) и **отключите** его.
   * **Решение (для Яндекс.Браузера):** Откройте `browser://settings/security` (или Настройки -> Безопасность), найдите **"Использовать безопасный DNS-сервер"** и **отключите** его.
   * **Решение (для Firefox):** Откройте настройки (`about:preferences`), перейдите в раздел **"Приватность и защита"** (Privacy & Security), прокрутите вниз до **"DNS через HTTPS"** (DNS over HTTPS) и выберите **"Отключить"** (Off).

2. **Внутренний кеш браузера**
   Сброс кеша Windows (`ipconfig /flushdns`) не влияет на браузеры — у них свой собственный, очень агрессивный кеш DNS и установленных соединений (Socket Pools).
   * **Решение (для Chrome):** 
     1. Перейдите по адресу `chrome://net-internals/#dns` и нажмите **Clear host cache**.
     2. Перейдите по адресу `chrome://net-internals/#sockets` и нажмите **Flush socket pools**.
   * **Решение (для Edge и Яндекс.Браузера):** Делается точно так же, как в Chrome, только используются другие внутренние адреса:
     * Для Edge: `edge://net-internals/#dns` и `edge://net-internals/#sockets`
     * Для Яндекс.Браузера: `browser://net-internals/#dns` и `browser://net-internals/#sockets`
   * **Решение (для Firefox):**
     1. Перейдите по адресу `about:networking#dns` и нажмите кнопку **Очистить кэш DNS** (Clear DNS Cache).
     2. У Firefox нет отдельной кнопки для сброса сокетов, поэтому после очистки DNS-кеша рекомендуется просто **перезапустить браузер**.

3. **Реальные прямые IP-адреса**
   Некоторые соединения действительно происходят напрямую по IP-адресу без участия DNS:  
   * Локальные прокси-серверы (например, `127.0.0.1:8080` для Nekobox/Xray).  
   * Запросы к локальному роутеру (например, `192.168.1.1` или `192.168.1.1:53`).
   * Приложения, в которых IP-адреса жестко прописаны в коде (hardcoded).
