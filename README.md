# 🛰️ NetTracker

**NetTracker** — это компактная консольная утилита для Windows. Она позволяет выбрать любое приложение (например, браузер, мессенджер или незнакомую программу) и в реальном времени увидеть, к каким серверам в сети оно подключается и какие DNS-имена запрашивает.

Утилита использует механизм **Event Tracing for Windows (ETW)**, что позволяет перехватывать события на уровне ядра ОС. Это гарантирует, что ни одно кратковременное сетевое соединение не будет пропущено и позволяет получать информацию о нём без установки драйверов или захвата пакетов.

## 🌟 Особенности
- **Глубокая аналитика:** Встроенный генератор отчетов выявляет подозрительные всплески активности (Burst-запросы), обходы DNS и анализирует CGNAT-адреса.  
- **Оффлайн-анализ:** Умеет загружать ранее сохраненные дампы трафика без прав администратора для дальнейшего изучения и конвертации в другие форматы.  
- **Умный экспорт:** Сохранение данных в форматы `JSON`, `CSV` или `hosts` (с фильтрацией дублей). Поддержка динамических макросов (например, `{%date%time}`) в именах файлов.  
- **Точность до миллисекунд (ETW):** Перехват событий происходит на уровне ядра ОС (Event Tracing for Windows), гарантируя хронологическую точность без внедрения сторонних драйверов.
- **Высокое разрешение:** Поддержка **миллисекунд** в логах для точного отслеживания очередности запросов.
- **Интеллектуальный DNS Resolution:** IP-адреса сопоставляются с реальными
  доменными именами на лету: NetTracker перехватывает и анализирует системные
  DNS-ответы (провайдер событий `Microsoft-Windows-DNS-Client`), поэтому в
  выводе вместо «сырых» адресов отображаются понятные имена вроде
  `api.github.com`. Это работает без обратных DNS-запросов (PTR) и без
  внешних справочников — только на основе фактических запросов вашей системы.
- **Умное управление сессиями и UAC:** Автоматический запрос прав администратора при запуске из проводника и поддержка флага `--elevate` для консоли.
- **Умное управление сессиями:** Понимает, откуда запущена (cmd/powershell или проводник), не закрывает окно после завершения и умеет сама запрашивать права администратора.
- **Мониторинг группы процессов:** Возможность одновременного отслеживания трафика нескольких приложений (например, браузера и прокси-клиента).
- **Интеллектуальная фильтрация:** Утилита отображает трафик только для указанных пользователем процессов, отсекая лишний системный шум.  
- **Стабильность и гигиена:** Использование уникального идентификатора сессии (`frolbel.NetTracker.Session`) с механизмом автоматической очистки зависших сессий при запуске и корректным освобождением ресурсов при выходе.
- **Zero-Dependency:** Не требует драйверов (WinPcap/Npcap), сторонних анализаторов трафика или установленного .NET Runtime. Поставляется одним компактным `.exe` — «self-contained Single-File Executable»

## ⚙️ Требования
- Операционная система: Windows 10/11 x64.
- **Права Администратора:** Необходимы для доступа к трассировке событий ядра (ETW).

## 🚀 Как получить утилиту

### Способ 1: Готовый файл (Рекомендуемый)  
Вы можете скачать уже скомпилированный исполняемый файл, который не требует установки:  
1. Перейдите в раздел **[Releases](https://github.com/frolbel/NetTracker/releases)**.
2. Скачайте файл `NetTracker.exe`.  
3. **Проверьте целостность (Опционально):**   
   - На странице релиза рядом с файлом в списке `Assets` найдите значение `sha256:...` и скопируйте его (кнопка с иконкой двух квадратов).
   - В папке со скачанным файлом откройте **PowerShell** и выполните команду:
     ```powershell
     Get-FileHash .\NetTracker.exe -Algorithm SHA256
     ```
   - Убедитесь, что значение в колонке `Hash` совпадает со скопированным с сайта.

### Способ 2: Сборка из исходников
Если вы хотите собрать программу самостоятельно, вам понадобится **.NET 9.0 SDK**:
1. Склонируйте репозиторий.  
2. Выполните команду в папке проекта:     
```bash   
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
```  
3. Готовый файл появится в папке `bin/Release/net9.0/win-x64/publish/`. 

## 🛠 Примеры использования

### 1. Интерактивный запуск
Просто перетащите файл анализируемой программы (например, `chrome.exe`) на иконку `NetTracker.exe`. Если потребуются права администратора, утилита сама запросит их через стандартное окно Windows.

💡 Можно также дважды кликнуть по файлу `NetTracker.exe` в проводнике — или,
что надёжнее, вызвать контекстное меню правой кнопкой мыши на файле
`NetTracker.exe` и выбрать «Запуск от имени администратора». Далее ввести одно или несколько имен процессов через пробел или запятую (например: `chrome`, `telegram`, `discord`) и нажать `Enter`.

### 2. Базовый мониторинг из консоли
Используйте флаг `--elevate` (или `-e`), чтобы утилита автоматически запросила UAC и открыла окно мониторинга:
```cmd
.\NetTracker.exe [<имя_процесса1>] [<имя_процесса2>] ... --elevate
```  
или для `Google Chrome`:  
```cmd
NetTracker.exe chrome --elevate
```
Здесь **Флаг** `--elevate` (или `-e`) позволяет принудительно запросить повышение прав (UAC) при запуске из обычной консоли, боле подробно см. [**Справочник командной строки (CLI Reference)**](docs/CLI_REFERENCE.md). 
    - **Без флага:** утилита выведет сообщение об ошибке в текущую консоль и завершится с кодом `5` (Access Denied). Это стандартное поведение для консольных утилит.
    - **С флагом:** Утилита инициирует запрос UAC и откроет **новое** окно административной оболочки (CMD или PowerShell), в котором продолжит работу.

### 3. Мониторинг группы процессов с сохранением в CSV
Отслеживание сразу нескольких программ. Файл будет сохранен с текущей датой и временем.
```cmd
NetTracker.exe telegram whatsapp --elevate --out="C:\Logs\chat_{%date_%time}.csv"
```

### 4. Создание блок-листа для файла hosts
Перехват трафика с генерацией заглушек (`127.0.0.1`), игнорируя прямой IP-трафик.
```cmd
NetTracker.exe bad_app.exe --elevate --out=".\blocklist.txt" --type=dummy
```  

### 5. Оффлайн-анализ (без прав администратора)
Загрузка вчерашнего дампа, вывод на экран и генерация аналитического отчета об аномалиях:
```cmd
NetTracker.exe --in="C:\Logs\chat_2026-11-25.csv" --stats=".\report.txt"
```

> 💡 **Совет:** Полный список команд, таких как `--loglevel` и параметры статистики, смотрите в [Справочнике CLI](docs/CLI_REFERENCE.md).

## Сравнение с альтернативными инструментами

| Критерий | NetTracker | TCPView | Wireshark |
| :--- | :--- | :--- | :--- |
| **Размер и портативность** | ~71,7 МБ, один файл | Запускается без установки, есть графический интерфейс | Для захвата пакетов в Windows обычно требуется Npcap |
| **Принцип работы** | Сбор сетевых событий через ETW | Периодическое обновление списка TCP-соединений и UDP-портов | Захват и декодирование сетевых пакетов |
| **Нагрузка на CPU** | Зависит от частоты событий и их обработки | Зависит от частоты обновления и размера списка | Зависит от объёма трафика и глубины разбора |
| **Офлайн-анализ** | Встроенный анализ аномалий | Сохранение текущего списка для последующего просмотра | Анализ сохранённых захватов в форматах PCAP и PCAPNG |
| **Основной сценарий** | Анализ истории сетевой активности приложений и связанных доменов | Просмотр TCP-соединений, UDP-портов и связанных с ними процессов | Диагностика сетевых протоколов на уровне пакетов |

См. [подробное сравнение NetTracker с альтернативными инструментами](docs/COMPARISON.md).
